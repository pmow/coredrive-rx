# CoreDrive RX v1.12.0

An Advert's Ed25519 signature is the only cryptographic proof of identity MeshCore
offers. Everything else in a packet is plaintext and attacker-chosen: the pubkey, the
name and the self-reported position are whatever the sender wrote, and hop counts, paths
and prefixes carry no MAC. This app's capture rule covers provenance, "record only what
was heard directly", and says nothing about authenticity, so a 0-hop advert can be
genuinely heard direct and still name a node that does not exist. Adverts captured here
are published to CoreScope, the registry the name resolvers read from, so one forgery
heard by one driver becomes a named node on someone else's screen.

## What's new

- **`verifyAdverts`: check an advert's signature before recording its identity.** The
  app now assembles the exact message the firmware signs, `pubkey(32) || timestamp(4,
  LE) || app_data` with `app_data` truncated to 32 bytes, and verifies the 64-byte
  Ed25519 signature over it. The timestamp goes in as the raw wire bytes rather than a
  re-encoded value, so nothing can disagree with what was received.

  An advert that fails **loses its identity, not its reception**. The SNR, RSSI and GPS
  position are still published, unattributed, because the measurement is real whoever
  wrote the advert; only the name attached to it is worthless. The node also stops being
  a region-discovery candidate, so the app never sends an anonymous request to an
  address somebody invented. This is deliberately narrower than Mesh-Hunter, which
  refuses the whole reception: that project is about identity, this one is about
  coverage.

  Rejections are named in the debug log. "No advert in the capture" and "advert
  rejected" are otherwise the same silence.

## Upgrade notes

- **`verifyAdverts` is off unless your `config.json` sets it to `true`.** It is the only
  flag that is off both when absent and when no config loaded at all, and the only one
  that makes the app record less than it heard. Turning it on is a deployment decision,
  not something to inherit by upgrading.
- **Service-worker cache bumped to `coredrive-rx-v40`.** Clients pick up the new bundle
  on their next load with a connection.
- **No MQTT contract change.** No new field, no new topic, so no ingestor work is needed
  to accept this release.
- **New dependency: `@noble/ed25519` 3.2.0.** Bundle 435.17 kB to 442.78 kB, gzip 136.22
  to 139.71.
- **Not exercised against a real forgery.** The gate is proven against the captured
  advert in the fixtures, which verifies against its own signature, and against a signed
  synthetic advert. Nobody has transmitted a forged advert at it.
- Tests: 255 pass (+16).
